# PICKSFOLIO - Daily Curation Platform

일상을 큐레이션하는 하이엔드 링크인바이오(Link-in-bio) 플랫폼입니다.

## 주요 기능
- **AI 트렌드 스카우트**: 무신사, 올리브영 등 주요 플랫폼의 실시간 트렌드 분석
- **그리드 템플릿**: 감각적인 디자인의 포트폴리오 및 링크 관리
- **커스텀 도메인**: 개인 도메인 연결 지원

## 기술 스택
- **Frontend**: React 19, Vite, Tailwind CSS
- **Backend**: Supabase (Auth, Database)
- **Deployment**: Vite Build System

## 시작하기

1. 저장소 클론:
   ```bash
   git clone <your-repository-url>
   ```

2. 패키지 설치:
   ```bash
   npm install
   ```

3. 환경 변수 설정:
   `.env.example` 파일을 참고하여 `.env` 파일을 생성하고 필요한 API 키를 입력하세요.

4. 로컬 실행:
   ```bash
   npm run dev
   ```

## 배포
이 프로젝트는 Vite를 사용하여 빌드됩니다.
```bash
npm run build
```
빌드된 결과물은 `dist` 폴더에 생성됩니다.
# 결제 운영 설정
## 배포 전 확인

- 인증문자 전체 일일 상한은 기본 1,000건입니다. 서버 환경변수 `SMS_VERIFICATION_DAILY_LIMIT`가 없으면 1,000건을 적용하고, 양의 정수로 설정하면 해당 값으로 변경할 수 있습니다. 기존 환경변수가 있다면 `1000`으로 설정해 주세요. 빈 값·잘못된 값·한도 저장소 오류에서는 발송을 차단합니다. 기준은 한국 시간 날짜이며, 번호별 10회/일 및 IP별 30회/일 제한도 유지합니다. 공급자 요청 이후의 실패·결과 불명은 사용량에서 차감하지 않습니다. 이 상한은 인증문자 경로에 적용되며 알림톡 대체 문자와 공급자 자체 재시도 비용까지 합산한 금액 상한은 아닙니다.
- 로컬 인증문자도 운영과 동일한 데이터베이스·Blobs 한도 검사를 거칩니다. Netlify Dev의 서비스 바인딩을 사용하거나 `NETLIFY_DB_URL` 및 Blobs 실행 컨텍스트를 제공해야 합니다. `tsx server.ts`에 Solapi 키만 넣어서는 실문자를 보내지 않습니다. 인증번호를 응답으로 반환하는 기존 개발용 우회 경로는 제거했습니다.
- 정기결제는 `membership-billing-background`가 진행 위치를 저장하며 처리합니다. 예약 함수는 5분마다 상태를 확인하지만, 새 결제 주기는 기존처럼 하루 한 번 04:10(KST)부터 시작합니다. 서명에는 기존 `PORTONE_V2_API_SECRET`을 사용하며, 별도 분리를 원하면 `MEMBERSHIP_BILLING_WORKER_SECRET`을 설정할 수 있습니다. 가격·판매 플랜·해지 예약 규칙은 변경하지 않았습니다.
- 기존 Supabase DM 마이그레이션은 계속 필요합니다. 이번 변경에 새 SQL 마이그레이션은 없으며, 백업·배치·상한 기록용 Blobs 저장소는 함수 실행 시 생성됩니다.
- 결제·멤버십 조회는 기존 데이터를 이동하거나 삭제하지 않습니다. 예전 키의 정보는 읽기 호환을 유지하며, 인증된 구독·해지 요청에서는 조건부 쓰기로 필요한 필드만 복사합니다. 원본은 삭제하지 않습니다. 별칭으로만 남은 예전 결제 데이터의 일괄 이전은 운영자 확인 후 별도로 진행해야 합니다.
- Netlify Identity의 이메일·초대 여부만으로 관리자를 인정하거나 권한을 자동 부여하는 경로는 제거했습니다. 서버가 부여한 명시적 `admin` 역할만 인정하며, Supabase의 기존 관리자 로그인은 유지합니다. 배포 전에 기존 Identity 관리자에게 `app_metadata.roles`의 `admin` 역할이 있는지 확인해 주세요. 이메일 예외만으로 접속하던 계정은 권한을 명시적으로 부여해야 합니다. 이미 부여된 역할을 자동 회수하지는 않으므로 기존 관리자 명단의 검토도 필요합니다.
- 전달본에서 `/깃허브/`의 예전 빌드·백업과 서비스 소개서를 제외하고 `.gitignore`에 추가했습니다. 원본 자료는 기존 압축본에 보존했습니다. 원격 저장소에서 이미 추적 중인 파일과 과거 커밋까지 자동으로 삭제한 것은 아닙니다.
- Instagram DM·인사이트 호출은 `INSTAGRAM_GRAPH_VERSION`(`v25.0`, `_shared/instagram-metrics.mts`) 한 곳에서 관리합니다. 버전을 바꿀 때는 이 값만 수정하고 발송·조회를 다시 검증하세요.


나이스정보통신 카드 결제는 PortOne V2의 **실 연동** 채널만 사용합니다. Netlify의 production
환경에 `VITE_PORTONE_NICE_CHANNEL_KEY`를 PortOne 콘솔에서 발급한 운영 채널 키로 설정해야
카드 결제가 활성화됩니다. 서버 결제 검증에는 `PORTONE_V2_API_SECRET`이 필요합니다.
MID별 설정을 사용하는 현재 환경에서는 `VITE_PORTONE_NICE_CHANNEL_KEY_IM0029308m`을 기본
나이스정보통신 카드 채널로 인식합니다.
이 키에는 포트원 채널 관리에서 **나이스정보통신 / 신모듈 결제창 일반결제**로 등록한 운영
채널을 연결해야 합니다. 나이스정보통신은 일반결제와 API 수기·정기결제 MID가 다르므로,
정기결제용 MID 채널 키를 카드 일반결제 키로 사용하면 결제창 호출이 실패합니다.
운영 결제 완료 API는 PortOne 조회 결과의 채널 유형이 `LIVE`인 경우만 승인하며, 카드 결제는
나이스정보통신 채널인지 추가로 확인합니다. 테스트 채널 결제는 적립·주문·멤버십 활성화에
사용되지 않습니다.

테스트 채널 키는 소스 기본값으로 제공하지 않습니다. 운영 채널 키가 없거나 형식이 잘못되면
카드 결제 요청을 시작하지 않고 설정 오류를 표시합니다.
